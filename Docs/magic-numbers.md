# Magic numbers, hardcoded timing and duplicated values

**What this file is for.** Every number, timeout, threshold and duplicated string in OutlookAI
that a reader could reasonably ask "why that value, and what happens if it changes?" about,
with an answer. It is a standing inventory, not a one-off report: when you add a literal that
someone might one day have to reason about, add a row.

**Why it exists.** Two full audits of the codebase were run for the values below - one over the
VSTO add-in and the build/release infrastructure, one over the MCP server. Together they close
the "**Audit the codebase for other timers and time-based behaviour**" item in `TODO.md`, which
had been open since the update poll was found by accident while something unrelated was being
added, and which explicitly asked for "one pass to find polls that should be events, intervals
that no longer match what they wait for, and anything that assumes wall-clock time moves
forward smoothly".

**How a value gets fixed**, in descending order of strength. A comment is the weakest possible
fix and is the last resort, because the audit found a comment in `Installer.iss` claiming the
Office versions it wrote "match versions checked elsewhere" that had already stopped being
true:

1. one named constant, used everywhere;
2. a value **derived at runtime** from the thing it mirrors - a line count, an array length, a
   sentence built from the number rather than restating it;
3. a **test or build step that fails** when the two sides drift;
4. only then, a comment.

**Status** is one of:

* **Fixed** - the value no longer has the problem the audit found. Says how.
* **Kept - defensible** - the value is right and stays. Says why.
* **Open - needs a decision** - somebody has to choose. Says what the choice is.

**Where the drift guards live.** Cross-file invariants that no compiler can see are checked by
`.github/scripts/check-pinned-constants.ps1`, which runs as the first step of both
`.github/workflows/build.yml` (every pull request) and `.github/workflows/release.yml` (every
release, and again against the certificate actually imported for signing). It is runnable by
hand: `pwsh -File .github/scripts/check-pinned-constants.ps1`. Cross-assembly invariants that a
compilation *can* see are pinned by the T1 test suite instead.

## MCP server

Scope: `McpServer\OutlookAI.Core\`, `McpServer\OutlookAI.ComHost\`, `McpServer\OutlookAI.McpServer\`,
`McpServer\OutlookAI.RemediationTools\`, `McpServer\OutlookAI.McpServer.Tests\`,
`McpServer\Directory.Build.props`, `McpServer\README.md`.

**The one structural change this pass made.** The server is two assemblies with a one-way
dependency: `OutlookAI.ComHost` references `OutlookAI.Core`, never the reverse. `ComHostPolicy`
owns the OUTER budgets (the deadline after which a wedged COM host is killed); `MailService`
owns the INNER ones (how long a scan or a sweep may run inside it). Because Core cannot see
ComHost, every one of those relationships was previously carried by two literals in two
assemblies that happened to agree - which is precisely how an inner budget came to EQUAL its
outer one. `OutlookAI.Core\Com\ComOperationBudgets.cs` is now the single source, in Core so both
tiers can reach it, and both tiers derive from it. Nothing in it may be edited casually: each
value is either measured or derived from one that is.
